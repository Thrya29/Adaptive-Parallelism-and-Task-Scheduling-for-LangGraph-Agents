Adaptive Scheduler

decides, per request, which tasks run in parallel and which wait backend: …

1 · Plan

The request decomposed into tasks. Arrows are dependencies: a task starts only after the tasks pointing to it have finished. Tasks in the same column can run at the same time.

waiting running done failed cancelled

2 · Decision

Before running anything, the scheduler simulates each candidate configuration many times and picks the best trade-off of latency, tail latency and cost.

Run a request to see the decision.

3 · Execution timeline

Each bar is one model call, from start to finish. Overlapping bars ran in parallel; the dashed line is the predicted finish time.
